# 0008. Where the frontend departs from Better's template

Status: Accepted
Date: 2026-11-03

## Context

The frontend follows Better's template, `flask-react-template/src/apps/frontend` ([0004](0004-better-frontend-conventions.md)). The template is the default, not a blueprint. The app departs from it only when:

- a tool's own default or preset says otherwise;
- the template's way breaks something;
- it breaks a rule in `AGENTS.md`;
- the prototype says otherwise.

## Decision

| Template                                                                                                                                                                                                       | This app                                                                                                                                                                                                                                                  | Why                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Entry point `index.tsx`                                                                                                                                                                                        | `main.tsx`                                                                                                                                                                                                                                                | Vite's default ([0006](0006-recommended-setup-with-default-settings.md))                                                                                                                                                                                                                                                                                                                                                               |
| Folder layout: `async.hook.ts` in `contexts/`, `helpers/`, providers inside `contexts/`, flat `services/`, pages as `index.tsx` or `*.page.tsx`, `public.tsx` and `protected.tsx`, `common-types.ts`, `utils/` | As in [0009](0009-folder-structure.md): `hooks/`, `configuration/`, `providers/` beside `contexts/`, one folder per service domain, every page `*.page.tsx`, one `route-objects.tsx` with the guards in `routes/guards/`, `types/common.ts`, `utilities/` | [0009](0009-folder-structure.md) gives the reason for each folder                                                                                                                                                                                                                                                                                                                                                                      |
| Provider file also exports its hook                                                                                                                                                                            | The context and hook in `contexts/authentication.context.ts`, and the provider alone in `providers/authentication.provider.tsx`                                                                                                                           | The lint preset's rule `only-export-components` keeps Vite's hot reload working                                                                                                                                                                                                                                                                                                                                                        |
| Router rebuilt when the signed-in state changes                                                                                                                                                                | Router created once, outside React in `app.component.tsx`; the public and the signed-in routes each sit under a guard that redirects                                                                                                                      | Rebuilding the router leaves the address out of step with the screen: Home shows at `/sign-in` after signing in, and the sign-in page at `/` after signing out (seen on a local server). React Router asks for one router created outside the React tree ([`RouterProvider`](https://reactrouter.com/api/data-routers/RouterProvider))                                                                                                 |
| Formik with Yup                                                                                                                                                                                                | React Hook Form with Zod                                                                                                                                                                                                                                  | Formik's last release, [2.4.9](https://github.com/jaredpalmer/formik/releases/tag/formik%402.4.9), came out on 2025-11-10, while React Hook Form released [7.91.0](https://github.com/react-hook-form/react-hook-form/releases/tag/v7.91.0) on 2026-10-23 and Zod [4.6.7](https://github.com/colinhacks/zod/releases/tag/v4.6.7) on 2026-10-12. Zod also checks the app's configuration at startup                                     |
| Errors shown as a toast                                                                                                                                                                                        | Field errors under each field, and the server's reason in an alert at the top of the form                                                                                                                                                                 | The [GOV.UK Design System](https://design-system.service.gov.uk/components/error-message/) and [Nielsen Norman Group](https://www.nngroup.com/articles/errors-forms-design-guidelines/) place an error next to its field, and WCAG 2.2 success criterion [3.3.1](https://www.w3.org/WAI/WCAG22/Understanding/error-identification.html) asks that the field in error be identified and the error described in text; a toast disappears |
| Login page navigates on success, and the form reports through `onSuccess` and `onError`                                                                                                                        | The form shows the server's reason as React Hook Form's root error, which it clears on each submit; the public route guard sends the signed-in patient to Home                                                                                            | Navigating on success adds a second history entry, so Back seems to do nothing; an error kept across a retry is not announced again                                                                                                                                                                                                                                                                                                    |
| `useAsync` keeps `result` and `error` and throws a plain `Error`                                                                                                                                               | `useAsynchronous` keeps only the loading state and throws an `AsynchronousOperationError` that carries the message to show and the original error as its `cause`                                                                                          | Nothing reads `result` or `error` from it; keeping them re-renders every screen and holds the last patient's record after sign-out (`AGENTS.md` rule 10)                                                                                                                                                                                                                                                                               |
| `isUserAuthenticated()`, a function that reads storage                                                                                                                                                         | `isUserAuthenticated`, a boolean from Medplum's profile                                                                                                                                                                                                   | The profile is already React state; a function around it adds nothing                                                                                                                                                                                                                                                                                                                                                                  |
| `getConfigValue` reads `window.Config` on demand and returns `undefined` when a value is unset                                                                                                                 | `configuration`, read from Vite's environment and validated once when the app starts                                                                                                                                                                      | A missing value stops the app at startup and names the value, instead of failing on first use (`AGENTS.md` rule 7); Vite exposes `VITE_` variables at build time ([Vite](https://vite.dev/guide/env-and-mode))                                                                                                                                                                                                                         |
| `frontend/` import alias, mapped in `tsconfig.json`                                                                                                                                                            | Relative imports (`./sign-in-form`, `../../types`), with no alias                                                                                                                                                                                         | Relative imports need no `tsconfig` paths and no Vite resolve option, so the setup stays at its defaults ([0006](0006-recommended-setup-with-default-settings.md))                                                                                                                                                                                                                                                                     |
| `RouterProvider` from the DOM entry point                                                                                                                                                                      | `RouterProvider` from `react-router`                                                                                                                                                                                                                      | Under Vitest the DOM entry point loads a second copy of React Router                                                                                                                                                                                                                                                                                                                                                                   |
| `auth`, `async`, `config`, `ApiResponse`, `Props`, `app-shell`                                                                                                                                                 | `authentication`, `asynchronous`, `configuration`, `ServiceResponse`, `Properties`, `application-shell`                                                                                                                                                   | No abbreviations or shorthand (`AGENTS.md`)                                                                                                                                                                                                                                                                                                                                                                                            |
| Its own Tailwind components and tokens (`Button`, `Heading`, `Stack`, `Spacing`, `Variant`)                                                                                                                    | Base Web's components and theme tokens, used directly, with no style overrides                                                                                                                                                                            | Base Web is a complete component library ([0002](0002-base-web-for-the-ui.md)) and the prototype uses it directly; wrappers would only repeat it                                                                                                                                                                                                                                                                                       |
| `components/app-shell/sidebar-nav.tsx` and `nav-item.tsx`, its own navigation rows                                                                                                                             | `application-shell.tsx` renders Base Web's `Navigation` (`baseui/side-navigation`), with `navigation-link.tsx` as its link override: Base Web's `StyledNavLink` rendered as React Router's `NavLink`; no `nav-item.tsx`                                   | The prototype's sidebar is Base Web's `Navigation` at its defaults, and Base Web renders the rows. Base Web's link has no router behind it, so React Router's `NavLink` gives it the browser's own handling of Cmd, Ctrl and Shift-clicks, a replaced history entry for the page already open, and `aria-current`                                                                                                                      |
| `components/app-shell/user-menu.tsx`, an avatar menu in the top bar with "Log Out"                                                                                                                             | `account-summary.tsx` in the sidebar: avatar, name, "Account owner" and a "Sign out" button                                                                                                                                                               | The prototype shows the account at the foot of the sidebar and has no sign-out, so the button sits there                                                                                                                                                                                                                                                                                                                               |
| The mobile drawer built from a fixed `aside` and an overlay `button`                                                                                                                                           | Base Web's `Drawer` from the left, with `role="dialog"`, `aria-modal` and a label passed through its props                                                                                                                                                | Base Web has a drawer; its container has no dialog role of its own, so the props add it                                                                                                                                                                                                                                                                                                                                                |
| `AccountProvider` mounted at the app root, around the routes                                                                                                                                                   | `CarePlanProvider`, `AppointmentProvider` and `RecordSourceProvider` mounted on the signed-in routes, around `ApplicationLayout`, and each page's own data providers on that page's route                                                                 | A provider at the root keeps the last patient's data after sign-out, so the next patient on the same device would see it while their own loads. On the signed-in routes, the providers unmount when the patient signs out                                                                                                                                                                                                              |
| `useAsync` holds `result` and `error` for every caller                                                                                                                                                         | Each data provider holds its own result, error and loading state through `useAsynchronousResult`, which wraps `useAsynchronous`; `useAsynchronous` itself keeps only the loading state                                                                    | `useAsynchronous` also serves `AuthenticationProvider` at the root, where a kept result would hold the signed-in profile after sign-out                                                                                                                                                                                                                                                                                                |
| One error boundary around the whole app (Datadog's `ErrorBoundary`), showing `pages/error`                                                                                                                     | An `errorElement` on the routes: `PageError` in the shell for a page that fails, with the navigation kept; `ApplicationError` on its own screen for a failure outside a page                                                                              | The app uses React Router's data router, which catches every error while a route draws and shows its own screen with the stack trace (`_renderMatches` in `react-router` 7.18.5), so a boundary around `RouterProvider` never sees them. The page's text and its retry follow the template's `ErrorFallback`                                                                                                                           |
| Scripts in `src/apps/backend/scripts/`, run inside the backend                                                                                                                                                 | `scripts/` at the repository root, run by Node.js 26 (`npm run load:example`)                                                                                                                                                                             | The app has no backend. In Vite's setup, `src` is browser code checked with browser types (`tsconfig.app.json`), and Node.js code is checked by `tsconfig.node.json`, which includes `scripts`                                                                                                                                                                                                                                         |
| Deployed as one Docker image on Kubernetes, with the backend                                                                                                                                                   | Static files on Cloudflare Workers, deployed with Wrangler ([0016](0016-hosting-the-demo.md))                                                                                                                                                             | The app has no server of its own ([0001](0001-frontend-only-app-on-medplum.md)), so it needs no container: any host of static files serves it                                                                                                                                                                                                                                                                                          |
| Sign-up page sends the person to log in, with a toast, once the account is created                                                                                                                             | The new patient is signed in with the code Medplum returns, and the public route guard takes them to Home                                                                                                                                                 | Medplum's `startNewPatient` returns a sign-in code, so asking for the password just typed would add a step; the guard adds no history entry, as on sign-in ([0007](0007-authentication.md))                                                                                                                                                                                                                                            |
| Sign-up asks for the password twice ("Re-type Password")                                                                                                                                                       | One password field, with Base Web's button to reveal it                                                                                                                                                                                                   | The prototype shows one password field with a button to reveal it                                                                                                                                                                                                                                                                                                                                                                      |
| Sign-up always offered                                                                                                                                                                                         | Sign-up offered only when `VITE_SIGN_UP_ENABLED` is `true`                                                                                                                                                                                                | Medplum leaves open registration off by default, and a link it refuses leads nowhere ([0007](0007-authentication.md))                                                                                                                                                                                                                                                                                                                  |
| `pages/authentication/` with `authentication-page-layout.tsx` and `authentication-form-layout.tsx` for the login and sign-up pages                                                                             | `components/authentication-page-layout/`: one layout with the page's `main` landmark, its card and its title                                                                                                                                              | Pages get one folder each ([0009](0009-folder-structure.md)), so a layout both pages use is a component; the card is Base Web's `Card`, not a component of our own                                                                                                                                                                                                                                                                     |

## Consequences

- Engineers who know the template find the same layers and files, with the differences listed here. In place of the template's components they find Base Web's.

## Alternatives considered

- **Follow the template in every detail.** Not chosen: some of its patterns break under Vite's defaults, React Router's data router or the rules in `AGENTS.md`, as the table shows.
