# 0003. React 18, because Base Web does not run on React 19

Status: Accepted
Date: 2026-11-03

## Context

- The latest React is [19.3.1](https://github.com/facebook/react/releases/tag/v19.3.1). React 19 [removed `defaultProps` for function components](https://react.dev/blog/2024/04/25/react-19-upgrade-guide#removed-proptypes-and-defaultprops): defaults now have to be written as default parameters.
- Base Web 18.2.0, its latest release, still sets `defaultProps` on function components. In the published package, 27 files assign `defaultProps`, among them `Card` (`card/card.js`). On React 19 those components lose their defaults, and `Card` crashes.
- Base Web is developed against React `^18.2.0` (its `devDependencies`), even though its `peerDependencies` accept React 18 or later.
- Medplum's `@medplum/react-hooks` 5.2.13 supports React 18 and 19 (its [`peerDependencies`](https://github.com/medplum/medplum/blob/v5.2.13/packages/react-hooks/package.json)).

## Decision

Use React 18.3, the last React 18 line (`react` and `react-dom` 18.3.1), with matching `@types/react` and `@types/react-dom`.

## Consequences

- Every dependency we add must support React 18. For example, React Router 8 requires React 19.2.7 or later (its [`peerDependencies`](https://github.com/remix-run/react-router/blob/react-router%408.0.0/packages/react-router/package.json)), so if the app uses React Router it will be version 7.
- React 18 gets no new features. Moving to React 19 needs a Base Web release that drops `defaultProps` from its function components.
- Revisit this decision whenever Base Web publishes a release.

## Alternatives considered

- **React 19, patching Base Web locally.** Not chosen: a private patch of a third-party library has to be carried and re-applied on every upgrade, which is hard to maintain in an open source project.
- **React 19 with a different component library.** Not chosen: the component library is set by [0002](0002-base-web-for-the-ui.md).
